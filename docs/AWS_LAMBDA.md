# Lambda backend deployment

The GitHub Actions workflow builds `backend/Dockerfile.lambda`, pushes the image to ECR, and updates the existing `taasheera-api` Lambda function in `us-east-1`. It runs for backend changes on `main` or by manual dispatch. The Lambda Web Adapter serves the existing FastAPI app over API Gateway HTTP API.

## One-time AWS and GitHub setup

1. In AWS account `632630731308`, create an ECR repository named `taasheera-api` in `us-east-1`.
2. Build and push the image once, then create a Lambda function named `taasheera-api` from that ECR image. Select **Container image**, `x86_64`, and an execution role with CloudWatch Logs access. If `taasheera-api` already exists as a **Zip** function, create a new image function and update the workflow's `LAMBDA_FUNCTION` value and API Gateway integration; AWS cannot convert the package type in place.
3. Create an IAM role for GitHub Actions with an OIDC trust policy limited to `repo:mhs86/Taasheera:ref:refs/heads/main` (matching the repository name's case). Grant it ECR authorization, image push, and `DescribeRepositories` permissions; grant Lambda `GetFunctionConfiguration`, `UpdateFunctionCode`, `UpdateFunctionConfiguration`, and `PublishVersion` permissions scoped to `taasheera-api`. Allow Lambda to pull the ECR image. Add the role's full ARN as the GitHub repository variable `AWS_DEPLOY_ROLE_ARN`. The sample placeholder `YOUR_GITHUB_ACTIONS_ROLE` is not a real role. The deployment job stays skipped until this variable is set.
4. Configure the Lambda's production environment: `DATABASE_URL` (reachable PostgreSQL with the current Alembic schema), a random `JWT_SECRET` of at least 32 bytes, `AUTH_ALLOWED_ORIGINS` containing the exact HTTPS frontend origin, and `AUTH_COOKIE_SECURE=true`. Add `GOOGLE_CLIENT_ID` for Google sign-in and `GEMINI_API_KEY` if the assistant is needed. The app reads these as environment variables; supply sensitive values through private AWS configuration, never through git or GitHub Actions logs. Run `python migrate.py upgrade` against the database before sending traffic to a new schema version; the deployment workflow does not run migrations.
5. Connect an API Gateway **HTTP API** Lambda proxy integration to this function. Use a `$default` route and `$default` stage with auto-deploy, or create both `ANY /` and `ANY /{proxy+}` routes. Point the frontend's API proxy at the resulting API Gateway HTTPS endpoint.

The image includes Tesseract, but passport uploads are disabled because the current storage writes to local disk. Lambda's writable `/tmp` is temporary, and API Gateway/Lambda payload limits can reject the current 10 MiB upload. Enable uploads only after implementing private S3 storage and an upload path that supports the file size. Activity events remain in PostgreSQL; the optional JSONL mirror uses temporary `/tmp` storage.

To bootstrap ECR and Lambda from a machine with AWS credentials and Docker, build from the repository root with `docker build --platform linux/amd64 -f backend/Dockerfile.lambda -t 632630731308.dkr.ecr.us-east-1.amazonaws.com/taasheera-api:bootstrap backend`, authenticate Docker to ECR, push that image, then create the image-based Lambda in the AWS console. Once GitHub and AWS prerequisites are set, use **Actions → Deploy Backend Lambda → Run workflow** to confirm the deployment. Check `/health/ready` through API Gateway afterward.
